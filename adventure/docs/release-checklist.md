# Release check for the little world

The current Site is a private prototype. The owner-approved town environment is integrated, and its offline composition has been reviewed against the reference. Static validation and model-level tests help catch regressions, but do not establish how the game feels or performs on a real device; browser/device QA remains unverified.

## Checks in this workspace

- `npm run typecheck`, `npm run test:dialogue`, `npm run test:arcade`, `npm run test:achievements`, `npm run test:audio`, `npm run test:phaser`, `npm run test:overlay-pause`, `npm run test:sheets`, `npm run test:movement`, and `npm run test:world-motion` cover the models, audio lifecycle, Phaser listener cleanup, pause/resume behavior, movement, and sprite-sheet indexing. The DOM and audio tests use mocks.
- `npm run validate:world` checks the Phaser map parser, assets, interaction definitions, and approximate paths to interactions. `python3 art/bird-animation/verify.py` checks the bird poses and their editable sources.
- `npm run test:collisions` checks object-linked footprints, the formerly blocked grass, and actual Phaser Arcade Physics movement against the exported map. Native-scale collision feel still needs a device playtest.
- `npm run test:group-collisions` checks a 96px gap between the fountain medallion and the whole garden, including its landing, then walks that passage with the real physics engine. It also compares the single static-group collider with individual colliders, including both sides of the river and bridge. `npm run test:residents` checks each background resident's animation and route. `npm run test:world-layering` checks the canopy and nameplate ordering. `npm run test:pixel-photos` checks the frame-preview scaling.
- The owner approved the town environment pack on 2026-11-12. `/art-review/index.html` remains its reference gallery; `public/art-review/manifest.json` records the historical reviewed map hash and final integrated map hash. `npm run validate:art-review` checks gallery dimensions, animation masks, fixed pixels, integrated-map hash, and runtime URL isolation. Gameplay assets live under `/game/town-v2/`; runtime URLs must not point to `/art-review/`.
- The offline composition was compared with `art/town-redesign/approved-reference.png`. Main streets retain 96px clearance; the garden and café stair approaches narrow to 66px and 78px to match the stonework. The northeast photo-garden arch is 69.75px wide. After owner screenshots exposed passable beds, `test:group-collisions` gained real-Phaser movement probes into visible garden, café and arcade solids, plus positive tests through the stairs and arch. The bed regression fails against the previous release. These checks and interaction reachability do not replace browser/device movement testing.
- The latest `npm run measure:release` measured 687 KiB raw / 206 KiB gzip for the initial HTML plus directly referenced CSS/JS, and 17.35 MiB across 209 files for the complete export. Phaser is 1.34 MiB raw / 356 KiB gzip and is not directly referenced by the initial HTML. These are file sizes, not measured network transfers; the lossless hero WebP is 2.45 MiB.
- The entry image uses a pixel-identical 2,565,086-byte WebP instead of the 2,974,504-byte PNG when WebP is supported. Sprite sheets reduce player/NPC image loads from 30 to 3 while retaining their source frames. The original files and fallback remain in the export, so the export size is not an initial-download size.
- Returning to character selection pauses the Phaser instance and retains its graphics in memory for faster re-entry; actual unmount or a graphics failure destroys it. Input is released while paused, arcade animation stops on unmount, and audio is disposed on exit. A version-checked Phaser patch unregisters visibility/focus listeners on destruction; a simulated-DOM test covers repeated and concurrent instances. Background tabs suspend audio and pause the arcade. Dialogs pause world rendering and release keyboard capture until closed. Real-browser memory and rendering still need measurement.
- The Help panel includes an alternative list to open interactions without movement. Changes to nearby targets and unlocked achievements are announced politely. The mobile interaction prompt hides the E key.
- The map's Places buttons mark a selected destination and give directions for the arcade and photo garden. The desktop hint shows G to resume walking after using the toolbar; mobile Interact indicates when the explorer needs to move closer. `npm run test:minimap` checks selection and clearing as well as map geometry. Recheck these flows on desktop and mobile browsers after deployment.

## Browser and device checks not yet performed

- Play Garden Glide with keyboard and with touch; assess flap/fall/death animation and the gradual difficulty through score 100. Check pause, replay, backgrounding, and closing mid-flight.
- Walk the new roads to the photo park, café and arcade, including the narrower photo-garden arch; check sign readability and picture frames with and without actual photos. Start, pause, resume and complete Milo's stamp trail, then play Market Match with keyboard and touch.
- Verify all three achievements, score migration, five minutes across separate visible visits, hidden-tab exclusion, reloads, and behavior if browser storage is unavailable.
- Test keyboard focus, screen-reader navigation, the Help interaction list, reduced motion, desktop resize, narrow mobile portrait and landscape, safe areas, and no horizontal clipping.
- Listen to audio on desktop and mobile with sound enabled and muted; verify it stops on exit, pauses in a hidden tab, and does not duplicate after repeated entries.
- Measure FPS and memory on representative desktop and mid-range mobile devices after repeated enter/exit cycles. The original goals are approximately 60 FPS on a recent laptop and at least 30 FPS on mid-range mobile; these are targets, not measured results.
- Review the integrated town, terrain borders, character animation, and arcade art at actual game scale. The Site is standalone; integration into the conventional portfolio remains a future task.
